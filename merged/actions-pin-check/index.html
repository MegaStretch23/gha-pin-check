Actions Pin Check

Paste a GitHub Actions workflow and see which uses: lines are not pinned to a full 40-character commit SHA (tags, branches, @main), and which patterns are risky: pull_request_target with a checkout of the pull request's code, ${{ github.event.* }} pasted into a run: step, permissions: write-all or no permissions: block, and curl | sh.

Private by construction. The check runs in this page. Your workflow is not uploaded and the page code makes no network calls. This is a heuristic, line-based check, not a security audit. The same rules ship as a one-file stdlib Python CLI (actions_pin_check.py) that can also look up the commit SHAs with --resolve.

What is checked

  • Pinning: a uses: owner/repo@ref whose ref is not a full 40-character commit SHA. A branch (@main, @release/v2) or a missing ref is a FAIL; a tag (@v4), an abbreviated SHA or a docker:// image without an @sha256: digest is a WARN. Local ./ actions are skipped.
  • pull_request_target: a workflow triggered by it whose actions/checkout step takes the pull request's head (github.event.pull_request.head.*, github.head_ref, refs/pull/.../merge) is a FAIL.
  • Script injection: ${{ ... }} in a run: step. Known attacker-controlled values (issue and pull request titles and bodies, comment bodies, github.head_ref, commit messages and author names) are a FAIL; other github.event.* values are a WARN. Pass them through env: and quote the variable.
  • Permissions: permissions: write-all is a FAIL; no top-level permissions: block together with a job that has none is a WARN.
  • curl | sh: curl or wget piped into a shell (also bash <(curl ...)) in a run: step is a FAIL.

Not covered: reusable workflows and composite actions, github-script script: blocks, whether a pinned commit is one you trust, and anything a line-based reader cannot see. The page does not look up SHAs (that needs the network); the CLI does with --resolve.
